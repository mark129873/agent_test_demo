# 晚灯

阿晚是一个虚构的成年角色。晚灯是运行在 Mac 本机的陪伴聊天应用：它记得你提过的事，重开后能接着聊，也支持录音、语音回复和照片。

## macOS 启动

需要 Python 3.11 或 3.12。打开「终端」，进入刚解压或克隆的项目目录：

```bash
cd /你的路径/agent_test_demo
python3 --version
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python app.py
```

如果 `python3` 不是 3.11 或 3.12，请用对应的 `python3.11` 或 `python3.12` 创建虚拟环境。然后在 Mac 浏览器打开 http://127.0.0.1:8765/ 。用 `Ctrl+C` 停止后端；下次只需在项目目录执行 `.venv/bin/python app.py`。记忆会保存在 `companion.sqlite3`。仅本机、单用户、单进程运行，不要直接暴露到公网。已在运行时，请回到原页面，不要再用同一份数据库启动另一个实例。

默认是**离线模拟**，不需 Key、不调用模型，用于先走通聊天。模拟不代表真实模型的理解与表达质量。真实聊天：打开「设置」，配置 OpenAI 官方 API 地址、账号可用的模型名（默认 `gpt-6-luna`）和自己的 Key，手动切换到 OpenAI。模型须支持 Chat Completions JSON 模式。真实请求会把本轮内容和相关上下文发往 OpenAI，且可能计费。可另行打开「在线会话摘要」，让后台分批整理旧对话；这会发送部分较早的聊天并产生额外模型调用，默认关闭。界面填写的 Key 以密文保存在本机 SQLite，重启可用；数据库旁的 `companion.sqlite3.credentials.key` 是本机加密文件（权限 600），不要提交或分享数据库和加密文件。也可以使用不落盘的 `OPENAI_API_KEY` 环境变量。旧版本仅在内存中的 Key 升级后需重填一次。

## 语音和照片

- 在「设置」选 OpenAI 并配置聊天模型，再打开「语音与媒体」。分别启用语音识别、语音合成或照片生成。每项有独立 Key、接口地址和模型；OpenAI 官方接口可继承文字服务的 Key。各服务单独填写的 Key 同样在 SQLite 加密保存，页面不回显。短视频不在本项目范围内。
- 点麦克风录音，再点方块停止。可以预听、重录或发送；语音转文字后沿用原来的聊天和记忆。浏览器需允许访问麦克风。默认接收方式可选文字、语音或两者。若本轮明确只要文字，不会调用语音生成；等语音时可展开文字，合成失败自动显示文字。
- 阿晚的语音用固定音色，按安慰、开心、深夜和日常场景改变节奏与语气。
- 可以索图，也可打开「允许阿晚偶尔主动分享照片」。主动照片只在话题相关、且距离上次分享足够久时发送。照片是阿晚虚构生活的画面，等待照片时仍可继续打字。
- 默认离线模式不调用任何媒体供应商。启用在线服务可能产生费用；仅启用文字不会自动开启媒体。录音、图片和语音结果保存在本机数据库；重启保留已完成媒体，未完成任务标记中断，不自动重试。媒体内容累计以 384 MiB 为限，达到上限后不主动清空聊天。可手动移除不需要的附件来腾出应用内空间；SQLite 文件不一定立即缩小。数据库与 WAL/SHM 文件只允许本机账户读写。

## 长期聊天怎么用

- 往上加载更早的聊天；换页、重启和摘要都不删原文。发送失败会保留原消息，可原地重试或点「不再等待」，后者保留原文但不再请求回复。
- 「记忆」可查看来源、更正、忘记。忘记不是删除历史。为防旧事实或派生回复再次进模型，更正或忘记会清空旧对话上下文和摘要，含有旧值的关联事件停止用于聊天与回访，其他独立记忆保留。事件也可在记忆页单独停用。新聊天继续积累，只有重新明确告知才会重新记下。
- 同类事件可分别记录或更改，例如「下周三有甲公司面试」「下周五有乙公司面试」「甲公司面试改到下周四」。无法确定是哪一件时先问，不改记录。对已约定的回访，可以说「不用问我会议讲得怎样了」撤销。「今晚别提同事那件事」只管到本地午夜，不删除原聊天。关页不推送；重开时只对已过 1–14 个本地日历日且仍待回访的普通事件问候一次。也可明确请阿晚在下次回来时问一句，如「明早开完会，可以问我讲得怎么样吗」，阿晚会说清最早何时可回访，而不假设知道你已结束。

## 技术设计

- `app.py` 负责 FastAPI、SQLite 与事务。请求 ID 防止重复受理，先保存用户消息，再按顺序生成回复；同一次请求等待同一个任务，一条消息通过 `reply_to` 绑定一条回复。页面按消息 ID 游标翻页，与模型上下文分开。开场问候不占用文本发送锁；入库前校验会话活动与事件版本。
- `continuity.py` 在预算内装入本轮、相关事实与有效事件，并为可用的历史摘要留出空间，再填入近期完整轮次。应用对 JSON 上下文实行 24 KB UTF-8 预算，不把它当供应商精确 token 数。摘要在后台增量生成，对不完整旧轮次等待，模型明确返回「这批没有可保留内容」才跳过，无效或空输出不推进，而且同批在本次运行中最多试两次；通过版本检查防止旧结果恢复已忘记信息。
- `events.py` 保留每个事件的 ID、版本和原话；改期、结束、取消只更新能明确识别的事件。旧版事件表就地迁移，升级不清空聊天、附件和密钥。
- `agent.py` 管理角色、离线行为、模型调用和记忆证据校验；`media.py` 管理录音转写、语音和照片的独立调用。当前在线适配基于 OpenAI 官方接口；分别配置不等于任意第三方 API 已接入。

## 本地验收

```bash
.venv/bin/python -m unittest discover -s tests -v
```

测试默认使用离线规则或自定义故障模拟，不调用真实供应商。可用 `COMPANION_DB` 指向新数据库，把试用与日常聊天分开。手动体验可先记下两个面试，改期其一、取消其一，再从「设置」用离线日期工具验证回访。真实陪伴语气、语音情绪、麦克风以及照片效果需要单独实测，不能用离线测试代替。
